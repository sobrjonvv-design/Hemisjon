# HEMIS Planner

Одностраничный студенческий планировщик на HTML5, CSS3 и Vanilla JavaScript. Без npm, сборщика и серверной базы данных. Готов для GitHub Pages. При первом открытии показывает явно обозначенные демо-данные.

## Обновление от 20 октября 2026 · версия 2026.10.20.2

Исправлена обработка ошибок запуска: если модуль JavaScript отсутствует или не загружается, вместо бесконечной заставки выводится понятное сообщение. При открытии index.html двойным нажатием сразу показывается инструкция запуска через start.bat. Обновлена версия офлайн-кеша; при плохом соединении кешированные файлы используются после 6 секунд ожидания сети. Задания и остальные локальные данные не очищаются.

Добавлена **check.html**: откройте её на опубликованном сайте, чтобы проверить наличие основных файлов, корректность JavaScript и версию страницы. Например, после адреса проекта добавьте `check.html`. Проверка не требует входа и не отправляет данные HEMIS. Для обновления существующего репозитория выберите **Add file → Upload files** и загрузите всё содержимое этой папки с заменой файлов. Сохраните через **Commit changes**. Настройки Pages оставьте **main → / (root)**. Дождитесь зелёной отметки в Actions, закройте прежние вкладки сайта и откройте сайт снова. Если у старой установленной PWA осталось старое оформление, сначала откройте обычную вкладку браузера с опубликованным адресом.

## Как запустить на Windows

1. Распакуйте всю папку.
2. Дважды нажмите **start.bat**.
3. Откроется **http://127.0.0.1:8080/**. Сервер работает в фоне.
4. Для остановки локального сервера нажмите **stop.bat**.

Нужен Windows PowerShell 5.1 или новее, который входит в Windows. Права администратора не требуются. `server.ps1` слушает только адрес 127.0.0.1. Если порт 8080 занят другой программой, освободите его или запустите сервер вручную на другом порту; адрес моста в `api.js` при этом тоже нужно изменить.

Не открывайте `index.html` двойным нажатием через `file://`: браузеры блокируют ES-модули и Service Worker в таком режиме. Используйте localhost либо HTTPS.

## Как загрузить на GitHub Pages

1. Создайте репозиторий на GitHub.
2. Выберите **Add file → Upload files**.
3. Загрузите **содержимое этой папки**, чтобы `index.html` находился в корне репозитория, а не внутри ещё одной папки. Сам ZIP-файл вместо исходников загружать не нужно.
4. Сохраните изменения кнопкой **Commit changes**.
5. Откройте **Settings → Pages → Build and deployment → Deploy from a branch**.
6. Выберите ветку **main** и папку **/ (root)**, затем **Save**.
7. После публикации откройте адрес, указанный в разделе Pages. Обычно это `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

Все пути относительные: приложение работает и в корне домена, и в подпапке репозитория. Маршруты используют `#schedule`, `#tasks` и т. д.; дополнительных правил перенаправления не нужно. Файл `.nojekyll` отключает ненужную обработку Jekyll.

Windows-файлы `server.ps1`, `start.bat`, `stop.bat` не исполняются на GitHub Pages. Их можно оставить в репозитории для локального запуска. Если загружаете только сайт, достаточно файлов HTML/CSS/JS, manifest, иконок и `.nojekyll`.

## Что работает

- Еженедельное расписание Пн–Сб, переключатель дней и отметка сегодняшнего дня по времени Ташкента.
- Живой статус пары, минуты до конца/следующей пары, сводка на сегодня и завтра. Обновление раз в минуту.
- Задания внутри предмета и дня недели: создание, изменение, удаление, приоритет, тип, дедлайн, заметки, ссылка на материалы.
- Подзадачи с чекбоксами и прогрессом; самостоятельный чекбокс завершения задания.
- Ручное добавление и изменение пар; проверка пересечений времени.
- НБ на карточках, аналитика по предметам, редактирование исходных часов. Неизвестная нагрузка не заменяется выдуманным числом.
- Локальное сохранение, импорт/экспорт JSON, поиск по предметам и заданиям.
- Синхронизация с отдельным паролем и ID студента без регистрации и отдельных API-токенов.
- Установка PWA и работа офлайн после первого успешного открытия.
- Настраиваемые вечерние уведомления при открытом приложении.

## Подключение HEMIS

В меню **Подключить HEMIS** выберите вуз и войдите логином/паролем либо вставьте готовый Bearer-токен. Доступны TIFT, TUIT, TDTU, TSUE, UzMU, student.hemis.uz и собственный HTTPS-адрес.

Запросы:

```text
POST /rest/v1/auth/login              {"login":"…","password":"…"}
GET  /rest/v1/education/schedule
GET  /rest/v1/education/subjects
GET  /rest/v1/education/attendance
```

Цепочка подключения: `http://127.0.0.1:8080/hemis-proxy` → прямой запрос → публичные прокси (только после включения соответствующего флажка). Публичные прокси получают Bearer-токен, поэтому по умолчанию выключены. Пароль авторизации через публичные прокси не передаётся. Ключи авторизации находятся в памяти текущего сеанса и не сохраняются в localStorage, JSON или облачных копиях.

Мост использует интернет-адрес вашего компьютера. Он обходит браузерный CORS в запросе к порталу, но не меняет Geo-IP. Некоторые браузеры ограничивают обращения к localhost с HTTPS-сайта: в этом случае откройте локальную версию через start.bat. На телефоне 127.0.0.1 указывает на сам телефон, а не на компьютер.

Мост разрешает только перечисленные порталы и четыре маршрута REST. Для своего вуза добавьте домен явным параметром запуска:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\server.ps1 -AdditionalAllowedHosts student.example.uz
```

Альтернатива подключению — **Вставить JSON**. Можно импортировать отдельный ответ расписания либо объединённый объект:

```json
{
  "schedule": [{"subject":{"id":71,"name":"Базы данных"},"day":1,"start":"09:00","end":"10:20","room":"B-208","type":"Лекция","teacher":"Д. Хакимов"}],
  "subjects": [{"id":71,"name":"Базы данных","total_hours":90}],
  "attendance": [{"id":1,"subject":{"id":71,"name":"Базы данных"},"excused_hours":2,"unexcused_hours":4}]
}
```

Адаптер поддерживает вложенные `data/items`, распространённые названия полей, даты вместо дней недели и пагинацию. Повторы одного еженедельного слота удаляются. Разные порталы и версии HEMIS могут иметь другую схему. Для неоднозначных данных показываются предупреждения. Если HEMIS возвращает `absent_on/absent_off` без признака `explicable`, текущий адаптер относит их к уважительным/неуважительным соответственно; проверьте эту интерпретацию у своего вуза и при необходимости исправьте `absence()` в `api.js`.

Реальный вход в аккаунт вуза без предоставленной учётной записи не проверялся. Успешность подключения зависит от конкретного портала, прав REST API, CORS, сети и формата ответа. Ошибки не подменяются демо-данными.

## Расчёт НБ

`пропуски = уважительные + неуважительные`; `процент = пропуски / часы предмета × 100`.

- Менее 15%: норма.
- От 15%: внимание.
- От 20%: критично.
- 25%: расчётный порог достигнут.

Индикатор заполняется относительно порога 25%. На карточке показывается число часов до достижения порога, включая граничный час. Это не обещание, сколько можно пропустить без последствий. Общую/аудиторную нагрузку и правила учёта уважительных пропусков сверяйте с вузом. Изменить часы можно нажатием на бейдж НБ.

## Синхронизация ПК ↔ телефон

1. На первом устройстве откройте **Синхронизация** и задайте ID студента и отдельный длинный пароль синхронизации.
2. Нажмите **Отправить в облако**.
3. На втором устройстве откройте тот же сайт и введите точно такие же ID и пароль.
4. Нажмите **Загрузить из облака** и примените найденную копию.
5. После изменений отправьте новую копию; на другом устройстве загрузите её.

Перед передачей снимок шифруется AES-256-GCM. Из ID и пароля PBKDF2/SHA-256 (600 000 итераций) выводит ключ и отдельный непрозрачный адрес канала. Ключ и пароль хранятся только в памяти, пароль нельзя восстановить. Публикация — простой POST с `Content-Type: text/plain;charset=UTF-8`, без нестандартных заголовков, чтение — GET.

**ntfy.sh хранит сообщения временно, обычно около 12 часов**, поэтому это перенос между устройствами, а постоянные копии сохраняйте через экспорт JSON. Бесплатный сервис имеет лимиты: перенос до ~40 КБ, до 16 частей, не чаще одного раза в 30 секунд. Для больших данных используйте JSON. Доступность и CORS внешнего сервиса могут изменяться. Поддержан ntfy; bytebin не используется, поскольку постоянное чтение одной записи без отдельного идентификатора не соответствует сценарию «только ID и пароль».

Защита от конфликтов проверяет известную ревизию перед отправкой и перед публикацией полного снимка. У ntfy нет атомарной блокировки: работайте с устройствами по очереди, сохраняйте JSON перед заменой данных. Автоматического слияния и фоновой отправки нет. Пустой канал может означать, что копии ещё нет, истёк срок хранения либо введены другие ID/пароль.

## PWA, офлайн и уведомления

Service Worker кеширует только собственные статические файлы приложения. Запросы HEMIS и ntfy, токены и ответы API в его кеш не попадают. После первого успешного открытия и установки Service Worker приложение открывается без сети; новые данные API и синхронизация требуют интернета. Inter и JetBrains Mono загружаются через Google Fonts при наличии сети, офлайн используются системные шрифты.

Уведомления включаются по явному действию в настройках. Время — Asia/Tashkent. Проверка выполняется раз в минуту, пока приложение открыто; фоновые вкладки браузер может приостанавливать. При закрытом приложении гарантировать уведомление ровно в 20:00 без push-сервера нельзя. На iOS поддержка зависит от версии системы и установки PWA на главный экран.

Обновление Service Worker применяется после закрытия открытых вкладок старой версии. При ручном изменении статических файлов увеличивайте `CACHE_VERSION` в `sw.js`.

## Данные и проверки

Основные данные сохраняются в localStorage, отдельно для пути установки сайта. Очистка данных браузера удалит локальную копию, поэтому периодически экспортируйте JSON. Экспортированный JSON не зашифрован. Перед восстановлением файла или облачной копии приложение проверяет схему, ссылки на предметы, даты, время и безопасные HTTP(S)-ссылки.

Проверено: 25 автоматических проверок чистой логики, нормализации API, границ 15/20/25%, смены даты UTC+5, шифрования/расшифровки между двумя сеансами и защиты ревизий с имитацией ntfy. В браузере проверены создание задания и подзадачи, чекбоксы и сохранение после перезагрузки. Реальный вход в HEMIS и отправка данных во внешний ntfy в ходе проверки не выполнялись.

Документация: [ntfy publish](https://docs.ntfy.sh/publish/), [ntfy subscribe API](https://docs.ntfy.sh/subscribe/api/), [HEMIS REST docs (могут требовать вход)](https://student.hemis.uz/rest/docs).
